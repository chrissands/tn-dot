## Migration authoring guide

Custom **form** block. Purpose: native forms defined in the document (first use: TDOT Maintenance Request, rebuilt from Formstack form 3533382).

### Authoring (Document Authoring)

Model: `standalone`

One block table. The first row names the columns; every following row is one field:

| Type | Name | Label | Options | Required | Show If | Style |
| --- | --- | --- | --- | --- | --- | --- |
| radio | emergency | Is this an Emergency…? | • Yes • No | true | | |
| callout | call-911 | **Call 911** | | | emergency = Yes | |
| select | request-type | Type of Maintenance Request | • Pavement Repair - Pothole = 401 … | true | emergency = No; hazard = No | |

- **Type**: `text`, `email`, `tel`, `number`, `textarea`, `select`, `radio`, `checkbox`, `name` (first/last; Options = the two sub-labels), `confirm` (must equal the field named in Options), `heading` / `note` / `callout` (rich text from Label), `submit` (button text in Label), plus settings rows:
  - `action` – URL that receives the answers (Label cell). Sent as a JSON POST: `{ "data": { "<name>": "<value>" } }`; coded options also send `<name>-label`. **Leave empty and the form shows the `error` message instead of sending.**
  - `success` / `error` – messages shown after sending / when sending fails.
  - `captcha` – Google reCAPTCHA v2 **Invisible** site key (Label cell). The reCAPTCHA script loads when a visitor starts using the form; on Submit (after validation) the token is sent as `g-recaptcha-response`, and the badge shows under the Submit button. The receiving endpoint must verify the token with Google (`https://www.google.com/recaptcha/api/siteverify`, using the secret key kept on the server). **A `captcha` row with an empty key blocks sending**; remove the row to use the form without reCAPTCHA.
- **Options**: one list item per option; `Label = value` stores a code different from the visible label.
- **Show If**: `name = value` conditions joined with `;` (all must match; `!=` negates). Hidden fields are not validated or sent.
- **Style**: `half` (half width from 600px), `half-right` (right column), `inline` (options side by side), `tall` (taller text area).
